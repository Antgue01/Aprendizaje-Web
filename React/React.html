React

React crea Single Page Applications (SPA). Un único `index.html` se carga y su contenido se actualiza dinámicamente en el navegador. Visualmente parece que navegas, pero lógicamente, todo ocurre en la misma página, sin recargas completas.

El principio de diseño ideal en React es que cada elemento o sección de la página sea un componente distinto, fomentando la modularidad y reutilización, por lo que el archivo index.html de una aplicación React contiene un único <div> con un id="root" (o similar), donde todo el contenido de la aplicación se inyecta y gestiona mediante JavaScript.

Set Up

La página se configura en el index.js, donde se importan tanto los componentes y los CSS como los módulos que sirven para crear y enrutar (asignar página a "url") los componentes de la aplicación.

import React from 'react'; import ReactDOM from 'react-dom'; import App from './components/App'; // O './App' si App.js está en la raíz import 'bootstrap/dist/css/bootstrap.min.css'; import HomePage from './pages/HomePage';
¡Copiado!

Finalmente, creamos el root y renderizamos. Para ello, llamamos a ReactDOM.createRoot(div con id "root") y a su método render(componentes).

const root = ReactDOM.createRoot(document.getElementById('root')); root.render( <React.StrictMode> <App /> </React.StrictMode> );
¡Copiado!

Si necesitamos usar fuentes o librerías ESTÁTICAS(no cambian nunca), las importamos en el index.html

La palabra clave class se reemplaza por className para evitar conflictos con JS.

Es recomendable la librería why did you render para profiling.

Enrutamiento

Para enrutar, es decir, asignar las URL a páginas de nuestra web de forma que cuando se escriba una URL nuestra, React tiene que saber cómo reconfigurar el DOM (o la View en native). Para ello usamos el módulo react-router-dom, que se descarga de yarn con el comando:

yarn add react-router-dom
¡Copiado!

Después, usamos el import correspondiente:

import { BrowserRouter as Router, Routes, Route, Link } from 'react-router-dom';
¡Copiado!

El componente Router se encarga de gestionar las rutas de nuestra aplicación, y además es donde se construye el nav que sobrevivirá entre páginas. Debe envolver toda la aplicación para que el enrutamiento funcione correctamente.

Si tiene componentes padre, estos también sobreviven entre páginas.

Dentro de Router, ponemos tanto los componentes visuales que formen nuestro nav (que en cada apartado del nav deben incluir el componente <Link to = { "ruta"} /> ) como el componente <Routes>, dentro del cual irán cada una de las rutas de la aplicación.

Para ello utilizamos el componente <Route path = { "ruta"} element = { <Componente />} /> , donde path es la URL y element es el componente que se muestra al acceder a esa URL (generalmente una página).

<Router> {/*Construcción visual del nav con <Link> */} <nav className='main__nav'> <ul> <li> <Link to={"/"}> <i className='bi bi-house-door'> </i> </Link> </li> <li> <Link to={"/rotating"}>Botón Rotativo</Link> </li> </ul> </nav> {/*Rutas lógicas*/} <Routes> <Route path="/" element={<App />} /> <Route path="/rotating" element={<RotatingButtonPage />} /> </Routes> </Router>
¡Copiado!

Podemos poner variables en las rutas, para ello utilizamos el símbolo : en la definición de la ruta, y en el componente al que redirigimos lo declaramos como prop y usamos el hook useParams.

<Route path="/pagina/:nombre" element={<MiPagina />} />
¡Copiado!

Luego, en el componente <MiPagina/> :

import { useParams } from 'react-router-dom'; export default function MiPagina() { const { nombre } = useParams(); // Hacemos lo que sea con el parámetro }
¡Copiado!

Así, al acceder a la URL /pagina/Pepe, recibiremos Pepe en el prop.

Es una sintaxis desarrollada para React que permite usar los componentes como etiquetas HTML. JSX se transpila (compilar de un lenguaje a otro) a JavaScript puro antes de ejecutarse en el navegador.

Esto hace que sea muy flexible, ya que podemos usar JSX dentro de bucles, con condicionales, variables,etc.

Para insertar variables y expresiones en JSX, usamos { }. Por ejemplo:

const image = <img src = {myImg.uri} alt = {myImg.alt}/>
¡Copiado!

Para definir componentes, se puede hacer principalmente de dos formas, a través de una función normal o a través de una función flecha.

function Hola() { return <h1> Hello World </h1>; }
¡Copiado!
const Hola = () => { return ( <h1> Hello World </h1> ); }

Los componentes pueden recibir argumentos en la función que los define para mostrar contenido personalizado o hacer lógica, son los llamados Props y, como dijimos antes, se insertarían con { } en el componente.

Para Pasar los props al componente, se hace como si fuera un atributo de la etiqueta HTML. Después, en el componente, se definen como un objeto deserializado.Por ejemplo:

En la App

<Hola name={"Adri"} age={23} />
¡Copiado!

En el componente

const Hola = (props) => { const { name, age } = props; return (<h1 className="title">Hey wassup, {name} are u {age} years old?</h1>); }
¡Copiado!

Renderizado Condicional

Es azúcar sintáctico para hacer condicionales dentro de JSX. Hay tres formas principales de hacerlo:

El operador ternario de toda la vida:

{condición ? <Componente si True/> : <Componente si false/>}
¡Copiado!

Un AND:

{condición && <Componente si True/>}
¡Copiado!

Un If / Else dentro del componente:

if (condición) { <Componente si True/> } else { <Componente si false/> }
¡Copiado!

Renderizado en Bucle

Cuando tenemos que renderizar una lista de elementos, podemos usar el método map de los arrays, que nos permite iterar sobre cada elemento y devolver un componente por cada uno. De esta forma:

export default function InfoGrid({ info } ) { {/*Info es un array que puede venir por ejemplo de una API REST*/} return {info.map((character,index)=>(<Character characterData={character}/>))} }
¡Copiado!

Hooks

Los Hooks son funciones que permiten a los componentes de React acceder a funcionalidades del ciclo de vida y del estado sin necesidad de crear una clase.

import { useState, useEffect } from 'react';
¡Copiado!

use State

useState permite añadir un estado local a un componente funcional.

Primero, tenemos que importarlo de react, y luego llamamos a la función useState(valor inicial), que devuelve un array con el estado y la función que hay que llamar para cambiarlo. Nosotros entonces lo declaramos en un array deserializado y ya podemos usarlo:

import { useState } from'react'; //Declaramos el estado const [state, setState] = useState(0); //Cambiamos el estado setState(1); // ... return <h1>{state}</h1>;
¡Copiado!

useEffect

El useEffect se usa para responder a cambios en el estado o props. Recibe una función y un array de dependencias.

La idea es que la función que pasamos se ejecute cada vez que alguna de las dependencias cambie, y si le pasamos una lista vacía, se ejecutará una sola vez, al montar el componente.

Si en el efecto creamos algo externo a React, como un intervalo, un listener o una conexión a una API externa, debemos limpiarlo al desmontar el componente, devolviendo una función de limpieza dentro del efecto. Por ejemplo, hacemos clear del intervalo o quitamos el listener.

De hecho, si no estamos en modo build, React ejecutará dos veces el efecto al montar el componente, y si ocurre algún error, significa que no hemos limpiado del todo el efecto, ya que debe soportar que el componente se monte, se desmonte y se vuelva a montar.

useRef

Como tras cada re-renderizado se pierden los valores de las variables, se utiliza este hook para crear variables que sobrevivan a estos re-renderizados.

Tiene un atributo current, que es donde guardamos y usamos la referencia que queremos mantener.

useContext

Si necesitamos pasar el mismo prop a muchos hijos(con el mismo o distinto valor), crearemos un contexto, que es como un objeto al que pueden preguntar los hijos y busca hacia arriba hasta llegar al primer padre que lo tiene .

Para ello, creamos un archivo loqueseaContext.js en el que creamos el contexto:

//loqueseaContext.js import { createContext } from 'react'; export const loqueseaContext = createContext(valor por defecto);

En el padre al que queremos preguntar envolvemos los hijos en nuestro contexto:

//Padre.js import { loqueseaContext } from './loqueseaContext.js'; export default function Padre({ level, children } ) { return ( //cosas del componente que renderizar //... <loqueseaContext.Provider value={level}> {children} </loqueseaContext.Provider> ); }
¡Copiado!

En el hijo usamos el hook useContext:

//Hijo.js import { useContext } from 'react'; import { loqueseaContext } from './loqueseaContext.js'; export default function Hijo() { const loquesea = useContext(loqueseaContext); //usamos loquesea }
¡Copiado!

useMemo

Cachea el resultado de una función para que no se vuelva a ejecutar en cada renderizado, lo que mejora el rendimiento. Pensado para funciones que tardan en ejecutarse.

La primera vez que se renderiza el componente, se ejecuta la función y se guarda el resultado.

En renderizados posteriores, si las dependencias no han cambiado, se devuelve el resultado guardado.

En cuanto cambia una dependencia, se vuelve a ejecutar la función y se actualiza el valor.

La sintaxis es la siguiente:

useMemo(fn, dependencies);
¡Copiado!
