React

React crea Single Page Applications (SPA). Un único `index.html` se carga y su contenido se actualiza dinámicamente en el navegador. Visualmente parece que navegas, pero lógicamente, todo ocurre en la misma página, sin recargas completas.

El principio de diseño ideal en React es que cada elemento o sección de la página sea un componente distinto, fomentando la modularidad y reutilización, por lo que el archivo index.html de una aplicación React contiene un único <div> con un id="root" (o similar), donde todo el contenido de la aplicación se inyecta y gestiona mediante JavaScript.

Beneficios

Set Up

La página se configura en el index.js, donde se importan tanto los componentes y los CSS como los módulos que sirven para crear y enrutar (asignar página a "url") los componentes de la aplicación.

import React from 'react'; import ReactDOM from 'react-dom'; import App from './components/App'; // O './App' si App.js está en la raíz import 'bootstrap/dist/css/bootstrap.min.css'; import HomePage from './pages/HomePage';
¡Copiado!

Finalmente, creamos el root y renderizamos. Para ello, llamamos a ReactDOM.createRoot(div con id "root") y a su método render(componentes).

const root = ReactDOM.createRoot(document.getElementById('root')); root.render( <React.StrictMode> <App /> </React.StrictMode> );
¡Copiado!

Si necesitamos usar fuentes o librerías ESTÁTICAS(no cambian nunca), las importamos en el index.html

La palabra clave class se reemplaza por className para evitar conflictos con JS.

Es recomendable la librería why did you render para profiling.

Enrutamiento

Para enrutar, es decir, asignar las URL a páginas de nuestra web de forma que cuando se escriba una URL nuestra, React tiene que saber cómo reconfigurar el DOM (o la View en native). Para ello usamos el módulo react-router-dom, que se descarga de yarn con el comando:

yarn add react-router-dom
¡Copiado!

Después, usamos el import correspondiente:

import { BrowserRouter as Router, Routes, Route, Link } from 'react-router-dom';
¡Copiado!

El componente Router se encarga de gestionar las rutas de nuestra aplicación, y además es donde se construye el nav que sobrevivirá entre páginas. Debe envolver toda la aplicación para que el enrutamiento funcione correctamente.

Si tiene componentes padre, estos también sobreviven entre páginas.

Dentro de Router, ponemos tanto los componentes visuales que formen nuestro nav (que en cada apartado del nav deben incluir el componente <Link to = { "ruta"} /> ) como el componente <Routes>, dentro del cual irán cada una de las rutas de la aplicación.

Para ello utilizamos el componente <Route path = { "ruta"} element = { <Componente />} /> , donde path es la URL y element es el componente que se muestra al acceder a esa URL (generalmente una página).

<Router> {/*Construcción visual del nav con <Link> */} <nav className='main__nav'> <ul> <li> <Link to={"/"}> <i className='bi bi-house-door'> </i> </Link> </li> <li> <Link to={"/rotating"}>Botón Rotativo</Link> </li> </ul> </nav> {/*Rutas lógicas*/} <Routes> <Route path="/" element={<App />} /> <Route path="/rotating" element={<RotatingButtonPage />} /> </Routes> </Router>
¡Copiado!

Podemos poner variables en las rutas, para ello utilizamos el símbolo : en la definición de la ruta, y en el componente al que redirigimos lo declaramos como prop y usamos el hook useParams.

<Route path="/pagina/:nombre" element={<MiPagina />} />
¡Copiado!

Luego, en el componente <MiPagina/> :

import { useParams } from 'react-router-dom'; export default function MiPagina() { const { nombre } = useParams(); // Hacemos lo que sea con el parámetro }
¡Copiado!

Así, al acceder a la URL /pagina/Pepe, recibiremos Pepe en el prop.

JSX

Es una sintaxis desarrollada para React que permite usar los componentes como etiquetas HTML. JSX se transpila (compilar de un lenguaje a otro) a JavaScript puro antes de ejecutarse en el navegador.

Esto hace que sea muy flexible, ya que podemos usar JSX dentro de bucles, con condicionales, variables,etc.

Para insertar variables y expresiones en JSX, usamos { }. Por ejemplo:

const image = <img src = {myImg.uri} alt = {myImg.alt}/>
¡Copiado!

Para definir componentes, se puede hacer principalmente de dos formas, a través de una función normal o a través de una función flecha.

function Hola() { return <h1> Hello World </h1>; }
¡Copiado!
const Hola = () => { return ( <h1> Hello World </h1> ); }

Los componentes pueden recibir argumentos en la función que los define para mostrar contenido personalizado o hacer lógica, son los llamados Props y, como dijimos antes, se insertarían con { } en el componente.

Para Pasar los props al componente, se hace como si fuera un atributo de la etiqueta HTML. Después, en el componente, se definen como un objeto deserializado.Por ejemplo:

En la App

<Hola name={"Adri"} age={23} />
¡Copiado!

En el componente

const Hola = (props) => { const { name, age } = props; return (<h1 className="title">Hey wassup, {name} are u {age} years old?</h1>); }
¡Copiado!

En este archivo se pueden también declarar la estructura de los JSON para que el compilador detecte errores y autocomplete al usarlos:

//declaramos el tipo del JSON type JSONAttributes = { color1: ColorValue, number1: number, string1: string, string2: string } //aquí la ruta y el * es para todos los archivos .json declare module '../themes/*.json' { const jsonAttrs: JSONAttributes; export default jsonAttrs; }
¡Copiado!

Renderizado Condicional

Es azúcar sintáctico para hacer condicionales dentro de JSX. Hay tres formas principales de hacerlo:

El operador ternario de toda la vida:

{condición ? <Componente si True/> : <Componente si false/>}
¡Copiado!

Un AND:

{condición && <Componente si True/>}
¡Copiado!

Un If / Else dentro del componente:

if (condición) { <Componente si True/> } else { <Componente si false/> }
¡Copiado!

Renderizado en Bucle

Cuando tenemos que renderizar una lista de elementos, podemos usar el método map de los arrays, que nos permite iterar sobre cada elemento y devolver un componente por cada uno. De esta forma:

export default function InfoGrid({ info } ) { {/*Info es un array que puede venir por ejemplo de una API REST*/} return {info.map((character,index)=>(<Character characterData={character}/>))} }
¡Copiado!

Pasar componentes como props

Esto es relevante sobre todo en Typescript. En React hay dos tipos para los componentes: ComponentType<Props> (la plantilla genérica <Props> es opcional) por una parte y ReactNode por otra.

Un componente es una función que recibe un objeto del tipo de la plantilla (Props ), por lo que podemos pasarle props desde fuera sin re-renders innecesarios.

Al invocarlo, se hace simplemente pasando la función.

Por otra parte, un nodo es una etiqueta JSX o TSX, por lo que los props que le pasemos serán fijos.

Al invocarlo, se hace entre {}.

Types.ts

// Archivo Types.ts (o bien sin los exports antes de implementar tu componente) import { ComponentType, ReactNode } from 'react' export type CustomCompNode = { //Esto es un nodo, un tsx. node: ReactNode; } export type CustomComp = { // Esto es un componente con dos props: un string y un número. // SIEMPRE VAN A SER ESOS DOS PROPS //Las variables de tipo componente tienen que empezar POR MAYÚSCULA Comp: ComponentType<{ text: string, number: number }>; // Esto son los props que le pasamos al componente props: { texto: string, numero: number } } //Si declaramos con plantilla que extienda otro tipo, //cada vez que lo invoquemos // PODEMOS HACER POLIMORFISMO DE COMPONENTES //En este caso, cuando definamos el componente, //en la signatura tenemos que añadir <T extends OtroTipo export interface BaseComp { baseText: string, baseNumb: number, } export interface DynamicComponent<T extends BaseComp> { Comp: ComponentType<T>, props: T } //Estas dos interfaces ya incluyen lo de BaseComp export interface CustomComp1 extends BaseComp { extendedAttr1: string } export interface CustomComp2 extends BaseComp { extendedAttr2: number }
¡Copiado!

Recibir Nodos

Esto sería un componente que recibe un nodo:

import React from "react"; import { ReactNode } from "react"; import { View } from "react-native"; type Props = { node: ReactNode } export default function ComponenteQueRecibeNodo({ node }: Props) { // Renderizamos el nodo entre {} return ( <View> {node} </View> ) }
¡Copiado!

Y esto sería un componente que le pasa un nodo (que puede tener hijos, por supuesto)

import { Image, Text, View } from "react-native"; import ComponenteQueRecibeNodo from "./ComponenteQueRecibeNodo"; import React from "react"; export default function ComponenteQuePasaNodo() { return ( <View> <ComponenteQueRecibeNodo node={ <View> <Text>Hola</Text> <Image source={{ uri: 'path' }} /> </View> } /> </View> ) }
¡Copiado!

Recibir un componente Fijo

Esto sería un componente que recibe otro componente con unos props fijos y determinados:

import React, { ComponentType } from "react"; // Este CustomComp es el del Types.ts type Props = { componente: CustomComp } export default function ComponenteQueRecibeComponenteFijo({ componente }: Props) { const { Comp, props } = componente; // Renderizamos el componente desestructurando el objeto con los props return ( <Comp {...props} /> ) }
¡Copiado!

Esto sería el componente que le pasa esos props:

import { View } from "react-native"; import ComponenteQueRecibeComponenteFijo from "./ComponenteQueRecibeComponenteFijo.tsx"; import React from "react"; import ComponenteCustom from "./ComponenteCustom.tsx"; export default function ComponenteQuePasaComponenteFijo() { return ( <View> <ComponenteQueRecibeComponenteFijo componente={{ Comp: ComponenteCustom, props: { text: "hola", number: 2 } }} /> </View> ) }
¡Copiado!

Y este el CustomComponent:

import React from "react"; import { Text } from "react-native"; export default function ComponenteCustom(props: { text: string, number: number }) { const { text, number } = props; return ( <Text>Hola {text} tienes {number} segundos</Text> ) }
¡Copiado!

Recibir un componente Dinámico

Esto sería un componente que recibe otro componente con unos props que pueden variar. Para ello, debemos usar una template de tipos.

export default function ComponenteQueRecibeComponenteDinamico<T extends BaseComp>(componente: DynamicComponent<T>) { const { Comp, props } = componente; //Renderizamos el componente desestructurando el objeto con los props return ( <Comp {...props} /> ) }
¡Copiado!

Este sería el componente que le pasa los props:

import { View } from "react-native"; import ComponenteQueRecibeComponenteDinamico from "./ComponenteQueRecibeComponenteDinamico"; import React from "react"; import ComponenteCustom1 from "./ComponenteCustom1"; import ComponenteCustom2 from "./ComponenteCustom2"; export default function ComponenteQuePasaComponenteDinamico() { return ( <View> <ComponenteQueRecibeComponenteDinamico Comp={ ComponenteCustom1 } props={{ baseText: "hola", baseNumb: 2, extendedAttr1: "adios" }} /> <ComponenteQueRecibeComponenteDinamico Comp={ ComponenteCustom2 } props={{ baseText: 'adios', baseNumb: 5, extendedAttr2: 4 }} /> </View> ) }
¡Copiado!

Este sería el ComponenteCustom1:

import React from "react"; import { Text } from "react-native"; import { CustomComp1 } from "./types"; export default function ComponenteCustom1(props: CustomComp1) { const { baseText, baseNumb, extendedAttr1 } = props; return ( <Text>Hola {baseText} tienes {baseNumb} segundos para {extendedAttr1}</Text> ) }
¡Copiado!

Y este sería el ComponenteCustom2:

import React from "react"; import { Text } from "react-native"; import { CustomComp2 } from "./types"; export default function ComponenteCustom2(props: CustomComp2) { const { baseText, baseNumb, extendedAttr2 } = props; return ( <Text>Hola {baseText} tienes {baseNumb} segundos O SUFRIRÁS {extendedAttr2} desgracias</Text> ) }

Hooks

Los Hooks son funciones que permiten a los componentes de React acceder a funcionalidades del ciclo de vida y del estado sin necesidad de crear una clase.

import { useState, useEffect } from 'react';
¡Copiado!

use State

useState permite añadir un estado local a un componente funcional.

Primero, tenemos que importarlo de react, y luego llamamos a la función useState(valor inicial), que devuelve un array con el estado y la función que hay que llamar para cambiarlo. Nosotros entonces lo declaramos en un array deserializado y ya podemos usarlo:

import { useState } from'react'; //Declaramos el estado const [state, setState] = useState(0); //Cambiamos el estado setState(1); // ... return <h1>{state}</h1>;
¡Copiado!

Si para cambiar el estado USAMOS el valor actual (por ejemplo, un contador, que usa el valor actual y le suma 1), en lugar de llamar a la función con la expresión que actualiza el valor directamente, le debemos pasar una función flecha cuyo argumento es el valor actual. Así:

setState(prev => prev + 1 );
¡Copiado!

Esto evita bugs , sobre todo si cambiamos el valor varias veces en poco tiempo.

useEffect

El useEffect se usa para responder a cambios en el estado o props. Recibe una función y un array de dependencias.

La idea es que la función que pasamos se ejecute cada vez que alguna de las dependencias cambie, y si le pasamos una lista vacía, se ejecutará una sola vez, al montar el componente.

Si en el efecto creamos algo externo a React, como un intervalo, un listener o una conexión a una API externa, debemos limpiarlo al desmontar el componente, devolviendo una función de limpieza dentro del efecto. Por ejemplo, hacemos clear del intervalo o quitamos el listener.

De hecho, si no estamos en modo build, React ejecutará dos veces el efecto al montar el componente, y si ocurre algún error, significa que no hemos limpiado del todo el efecto, ya que debe soportar que el componente se monte, se desmonte y se vuelva a montar.

¡Importante!

Si leemos o usamos el valor de un estado en el useEffect, NO podemos cambiar su valor, ya que si lo hacemos entraremos en un bucle infinito.

useRef

Como tras cada re-renderizado se pierden los valores de las variables, se utiliza este hook para crear variables que sobrevivan a estos re-renderizados.

Tiene un atributo current, que es donde guardamos y usamos la referencia que queremos mantener.

useContext

Si necesitamos pasar el mismo prop a muchos hijos(con el mismo o distinto valor), crearemos un contexto, que es como un objeto al que pueden preguntar los hijos y busca hacia arriba hasta llegar al primer padre que lo tiene .

Para ello, creamos un archivo loqueseaContext.js en el que creamos el contexto:

//1) Creamos contexto con undefined por defecto const ThemeContext = createContext<ThemeContextType | undefined>(undefined); //2) creamos y exportamos un componente Provider con los valores reales //Debe recibir un prop {children} con el tipo {children:ReactNode} export const ThemeProvider = ({ children }: { children: ReactNode }) => { //creamos un estado para manejar los datos que sea (en este caso un tema) const [themeState, setThemeState] = useState(defaultTheme); //conviene memoizar ya que no redefinos las cosas a no ser que cambien const value = useMemo(() => ({ theme: themeState, changeThemeFunc: changeTheme, }), [themeState, changeTheme]) return ( <ThemeContext.Provider value={value}> {children} </ThemeContext.Provider > ) } //3) Creamos y exportamos un Hook para usar los datos del tema. //Si llamamos a useTheme en un componente que no esté envuelto //por el Provider, lanzará la excepción por pasarle undefined export const useTheme = () => { const data = useContext(ThemeContext); if (data === undefined) throw Error("El tema es undefined"); return data; }
¡Copiado!

En el padre al que queremos preguntar envolvemos los hijos en nuestro contexto:

//Padre.tsx import { ThemeProvider } from './ThemeProvider.tsx'; export default function Padre({ level, children } ) { return ( //cosas del componente que renderizar //... <ThemeProvider value={level}> {children} </ThemeProvider> ); }
¡Copiado!

En el hijo usamos el hook que exportamos:

//Hijo.tsx import { useTheme } from './ThemeContext.tsx'; export default function Hijo() { const { theme, changeThemeFunc } = useTheme(); //usamos theme o la función changeThemeFunc }
¡Copiado!

useMemo

Cachea el resultado de una función para que no se vuelva a ejecutar en cada renderizado, lo que mejora el rendimiento. Pensado para funciones que tardan en ejecutarse.

La primera vez que se renderiza el componente, se ejecuta la función y se guarda el resultado.

En renderizados posteriores, si las dependencias no han cambiado, se devuelve el resultado guardado.

En cuanto cambia una dependencia, se vuelve a ejecutar la función y se actualiza el valor.

La sintaxis es la siguiente:

useMemo(fn, dependencies);
¡Copiado!

useCallback es el equivalente para funciones en lugar de resultados de funciones.

La regla para usarlos es:

Si DENTRO de la función de un componente DECLARAMOS algo Y LO PASAMOS COMO PROP a un hijo, o bien HACEMOS UNA FUNCIÓN MUY COSTOSA DENTRO de la función del componente, USAMOS estos hooks.

ReactNative

La principal diferencia es que tiene componentes nativos que se importan desde react-native. A los componentes se les da estilo a partir del prop style, que recibe un objeto con las propiedades de estilo, como si fuera CSS, pero en camelCase.

Lo ideal es crear este objeto con Stylesheet.create(). Aquí en lugar de selectores, creamos un objeto en el que cada propiedad tiene como clave la clase y como valor el objeto de estilo.

Además, no hay Grid, solo hay Flex.

Para renderizar listas, se utiliza el componente FlatList en lugar de hacer arrays. (Este componente ya tiene scoll, no usar una ScrollView con él).map(). Otra opción es SectionList si queremos agrupar los elementos en secciones.

Estos componentes reciben un prop data con el array de datos (objetos) a renderizar y un prop renderItem que recibe una función que devuelve el componente (obviamente, debe recibir los props necesarios) a renderizar por cada elemento del array. Además, podemos usar el prop keyExtractor para especificar una clave única para cada elemento.

Permiten callbacks como onEndReached para detectar cuando se llega al final de la lista y cargar más datos, o onRefresh para refrescar la lista.

const DATA = [ { id: 0, nombre: 'First Item', {/*lo que sea*/} }, {/*...*/} {/*Este es el render Item*/} const Item = ({nombre}) => ( <View style={styles.item}> <Text style={styles.title}>{nombre}</Text> </View> ); {/*En el componente:*/} <FlatList data={DATA} {/*Este es el componente generado al declarar const Item*/} renderItem={({item}) => <Item nombre={item.title} />} keyExtractor={item => item.id}/>
¡Copiado!

Si queremos scroll en una lista, debemos envolverla en un componente ScrollView y usar la propiedad contentContainerStyle para dar estilo a la parte de dentro.

Además, a este scroll podemos envolverlo con un KeyboardAvoidingView para evitar que el teclado cubra los campos de entrada. Le pondríamos el prop behavior en padding y un keyboardVerticalOffset para ajustar la posición.

Navegación

Necesitamos instalar la librería react-navigation y sus dependencias para poder navegar entre pantallas en React Native. Para ello, ejecutamos el siguiente comando:

yarn add @react-navigation/native yarn add react-native-screens react-native-safe-area-context
¡Copiado!

Este instala la navegación por pila (stack), pero para los otros simplemente cambiamos el nombre.

yarn add @react-navigation/stack
¡Copiado!

Después, en el mainActivity hay que hacer override de la función onCreate para llamar al super.

Tenemos 3 formas de navegar, por pila (stack), por pestañas(tabs) y por cajón(drawer)(Generalmente un modal que te aparece cuando desplazas a la izquierda).

Necesitamos instalar las librerías correspondientes para cada tipo de navegación e importar la función create...LOQUESEA...Navigator.

Fuera de la función App, creamos el navegador que queramos y lo guardamos en una constante. Por ejemplo:

const Stack = createNativeStackNavigator();
¡Copiado!

Esta constante tiene dos variables, que a la vez so componentes: Navigator y Screen.. Pues bien, creamos un componente <NavigationContainer> y dentro usamos el componente Navigator de la variable, en el cual pondremos como hijos los componentes Screen de la variable que queramos. Estos reciben los props name(nombre para navegar a esa pantalla) y component.

<NavigationContainer> <Stack.Navigator> <Stack.Screen name="Home" component={HomeScreen} /> <Stack.Screen name="Details" component={DetailsScreen} /> </Stack.Navigator> </NavigationContainer>
¡Copiado!

Para movernos, importamos el hook useNavigation y lo usamos dentro del componente en el que tengamos el botón. Este hook nos devuelve un objeto con la función navigate, que recibe como parámetro el nombre de la pantalla a la que queremos ir. También podemos usar estas otras funcinoes:

Funciones de navegación

  • goBack()

En Typescript, conviene en un archivo types.ts exportar un tipo con las rutas y parámetros que piden.P. ej:

export type NavigationRoutes = { "Main": undefined, "Settings": { isPremiumUser: boolean } }
¡Copiado!

Después, antes de llamar a useNavigation, definimos un tipo con la pantalla en la que estamos, por ejemplo, en Main:

import type { NativeStackNavigationProp } from "@react-navigation/native-stack"; import { NavigationRoutes } from '../utils/types' type MainScreenNav = NativeStackNavigationProp<NavigationRoutes, "Main">; export default function MainScreen() { const navigation = useNavigation<MainScreenNav>(); }
¡Copiado!

Esto hará que si olvidamos pasar los parámetros de error.

Drawer

Dentro de nuestras pantallas podemos poner Drawers, aunque no sea para navegación. Para ello, la pantalla devolverá un Drawer.Navigator, que tendrá una única Drawer.Screen la cual tendrá el contenido de nuestra pantalla en el prop component.

El contenido del drawer se pondrá en el prop drawerContent del Drawer.Navigator

También podemos poner dos drawers, aunque se haría con el drawer de React Native Drawer Layout, que exporta el componente <Drawer> . Pondríamos uno de estos y rellenaríamos su prop renderDrawerContent con el contenido del Drawer.

En nuestra App.tsx, pondríamos uno de estos. Dentro de este Drawer, pondríamos otro con el prop drawerPosition en el lado contrario y su contenido relleno, y dentro pondríamos ya la navegación normal de la aplicación.

import MainScreen from './screens/MainScreen.tsx'; import Settings from "./components/Settings.tsx"; import QueueViewer from "./components/QueueViewer.tsx"; function App() { const Stack = createStackNavigator(); const [leftOpen, setLeftOpen] = useState(false); const [rightOpen, setRightOpen] = useState(false); //Como estas dos funciones están dentro del componente, //cada vez que cambia algo en App se redefinen, así que //si vamos a pasarlas como prop, usar el useCallback const openRight = () => { setLeftOpen(false); //Hay que llamarlo porque internamente usa un bool distinto y hay que sincronizarlos. setRightOpen(true); } const openLeft = () => { setRightOpen(false); //Hay que llamarlo porque internamente usa un bool distinto y hay que sincronizarlos. setLeftOpen(true); } return ( <> <Drawer open={rightOpen} onOpen={openRight} onClose={() => { setRightOpen(false) }} drawerPosition='right' renderDrawerContent={Settings} > <Drawer open={leftOpen} onOpen={openLeft} onClose={() => { setLeftOpen(false) }} drawerPosition='left' renderDrawerContent={QueueViewer}> <NavigationContainer> <Stack.Navigator> <Stack.Screen name="Main" options={{ title: '', headerShown: false }} component={MainScreen} /> <Stack.Screen name="Settings" options={{ title: '', headerShown: false }} component={Settings} /> </Stack.Navigator> </NavigationContainer> </Drawer> </Drawer> </> ); }
¡Copiado!

Traducciones

Tanto en React como en React native, se usa una combinación de las librerías i18n y react-native-localize.

Lo primero que hay que hacer es instalarlas:

yarn add i18next react-i18next yarn add react-native-localize
¡Copiado!

Opcionalmente, para evitar almacenar las traducciones localmente (en móvil lo ideal es ALMACENARLAS), instalamos esta otra librería:

yarn add i18next-http-backend
¡Copiado!

Después, en la raíz del proyecto configuramos i18n en un archivo i18n.ts:

import i18n from 'i18next'; import { initReactI18next } from 'react-i18next'; import * as RNLocalize from 'react-native-localize'; // imports de los archivos de traducción import enCommon from './locales/en/common.json' import esCommon from './locales/es/common.json' // 1) Recursos agrupados por idioma y namespace. Aquí tenemos los archivos almacenados const resources = { en: { common: enCommon, }, es: { common: esCommon, }, }; // 2) Detector sencillo que usa la configuración del sistema const detectDeviceLanguage = () => { const locales = RNLocalize.getLocales(); if (locales && locales.length > 0) { // languageCode devuelve 'en', 'es', 'fr', ... return locales[0].languageCode; } return 'es'; }; i18n .use(initReactI18next) .init({ resources, lng: detectDeviceLanguage(), // idioma del sistema fallbackLng: 'es', // idioma si no hay traducción ns: ['common'], // namespaces, es decir, traducciones separadas por módulos //para no tener un solo archivo gigante defaultNS: 'common', interpolation: { escapeValue: false, // no escapar, React se encarga format: (value, format, lng) => { if (format === 'uppercase') return String(value).toUpperCase(); if (format === 'lowercase') return String(value).toLowerCase(); if (format === 'number') return new Intl.NumberFormat(lng).format(value); if (format === 'datetime') return new Date(value).toLocaleString(lng); return value; }, }, react: { useSuspense: false, // en RN conviene false para evitar Suspense issues }, }); export default i18n;
¡Copiado!

Después, en App.tsx importamos el archivo para que se ejecute, y las librerías necesarias. Además, envolvemos nuestra App en el componente de traducción:

import './i18n'; // Llamamos a la configuración de i18n, librería de traducciones import { I18nextProvider } from 'react-i18next'; import i18n from './i18n'; function App() { //Cambiamos idioma por el guardado en el teléfono useEffect(() => { //Como no podemos ejecutar funciones asíncronas directamente en un componente //creamos la función y luego la ejecutamos const checkSavedLanguage = async () => { const currentLang = i18next.languages[0]; const savedLang = await AsyncStorage.getItem('lang'); //Si tenemos guardado algún idioma lo cambiamos por ese if (savedLang && savedLang !== currentLang) i18n.changeLanguage(savedLang); }; checkSavedLanguage(); }, []); return ( <> <I18nextProvider i18n={i18n}> {/*los componentes de nuestra aplicación*/} </I18nextProvider> </> ); }
¡Copiado!

Crearemos la carpeta locales en la raíz del proyecto y en ella una carpeta por código de idioma, en las que metemos los json de cada módulo.

Para usarlo en nuestros componentes, usamos el hook useTraslation, que recibe el namespace y devuelve una función llamada t, la cual recibe la clave de la palabra a traducir en el JSON. Un ejemplo de Settings.tsx:

import { useTranslation } from "react-i18next"; export default function Settings(props) { {/*Preparamos función traductora, se le pasa el namespace que va a usar*/} const { t } = useTranslation('common'); return ( <View style={Style.container}> {/* usamos la función traductora con la etiqueta del namespace */} <Text>{t('settings')}</Text> </View> ); }
¡Copiado!

Interpolación

La interpolación es poner variables en las traducciones. Sirve tanto para plurales como para datos que cambian en runtime. Incluso admite plurales, los cuales los detecta si la variable count del JSON es mayor que 1. En el JSON se hace con {{}} de esta manera:

{ "welcome": "Hola {{name}}, tienes {{count}} mensaje nuevo", "welcome_plural": "Hola {{name}}, tienes {{count}} mensajes nuevos", }
¡Copiado!

En el código del componente, esto se usa pasándole un objeto con estas variables a t:

t('welcome', { count: 1 , name: 'Antonio'});
¡Copiado!

Renaimated

Es la librería de animaciones. Exporta una serie de hooks para usar dentro de los componentes.

Con useSharedValue(default) creamos una variable cuya propiedad value será la que actualicemos usando los hooks withTiming(valor al que transicionamos, objeto de configuración)o, si queremos hacerlo parecer que se mueve con físicas,withSpring(valor, objeto de configuración)

Además, podemos usar funciones para crear loops, secuencias o retrasos con withRepeat(), withSequence() y withDelay()

Ahora bien, necesitamos crear un objeto de estilo que soporte sharedValues. Para ello, usamos la función useAnimatedStyle(función factoría). La función factoría simplemente debe devolver un objeto de estilo. Por ejemplo:

const scaleDown = useAnimatedStyle(() => ({ transform: [{ scaleY: scaleShared.value }], opacity: opacityShared.value }));
¡Copiado!

Este objeto de estilo se pasa a un componente de Reanimated. Por ejemplo, <Animated.View/>. Reanimated tiene versiones para la mayoría de componentes nativos para aceptar animaciones.

De todas formas, si tenemos componentes de librerías o complejos, podemos convertirlos para que sus props acepten sharedValues. Para ello, pasamos el componente por la función createAnimatedComponent(comp), que recibe un componente y te devuelve su versión convertida. CONVIENE MEMOIZARLO para poner la animación correcta de nuevo.

A estos componentes les podemos animar los props con la función useAnimatedProps(factoría).

const AnimatedCircle = Animated.createAnimatedComponent(Circle); export default function App() { const r = useSharedValue<number>(20); const handlePress = () => { r.value += 10; }; const animatedProps = useAnimatedProps(() => ({ r: withTiming(r.value), })); return ( <View style={styles.container}> <Svg style={styles.svg}> <AnimatedCircle cx="50%" cy="50%" fill="#b58df1" animatedProps={animatedProps} /> </Svg> <Button onPress={handlePress} title="Click me" /> </View> ); }
¡Copiado!

También podemos gestionar gestos como Pinch mediante eventos, y podemos usar la función withDecay() para controlar la inercia del gesto (por ejemplo que el usuario haga swipe más rápido o más lento).
